# Project Schedule
## Laboratory Data Governance, Quality and Interoperability Programme

**Document Version:** 0.1  
**Document Status:** Draft  
**Project Duration:** 6 Weeks  
**Prepared by:** Project Manager / Business Analyst

---

## 1. Project Timeline Overview

The project is planned over six weeks. Each phase has specific activities, deliverables and completion criteria.

| Week | Phase | Main Activities | Expected Deliverables |
|---|---|---|---|
| Week 1 | Project Initiation and Planning | Finalise project charter, BRD, stakeholder analysis, RACI and project governance | Approved planning documentation |
| Week 2 | Dataset Assessment | Identify dataset structure, inspect available fields, assess data volume, completeness and limitations | Dataset Assessment Report |
| Week 3 | Data Quality and Governance | Define data-quality dimensions, identify quality issues, establish validation rules and exception categories | Data Quality Framework |
| Week 4 | Terminology and Interoperability | Review LOINC coding, assess terminology consistency, define unit standardisation rules and prepare OMOP mapping specifications | LOINC Governance and OMOP Mapping Specification |
| Week 5 | Dashboard and Testing | Develop a data-quality dashboard, define test scenarios and perform initial validation | Dashboard Prototype and Test Results |
| Week 6 | Project Closure | Review deliverables, document findings, prepare implementation roadmap and final presentation | Final Project Report and Closure Documentation |

---

## 2. Detailed Activity Schedule

### Week 1 – Project Initiation
- Define project objectives and boundaries.
- Identify key stakeholders.
- Document business requirements.
- Define roles and responsibilities.
- Establish project risks and milestones.

**Completion criteria:** Planning documents are prepared and internally reviewed.

### Week 2 – Dataset Assessment
- Obtain the selected public dataset.
- Review dataset documentation and licensing.
- Identify available variables and data formats.
- Assess missing values and duplicate records.
- Document dataset limitations.

**Completion criteria:** Dataset structure and suitability are documented.

### Week 3 – Data Quality and Governance
- Define data-quality dimensions.
- Establish completeness and validity checks.
- Identify inconsistent test names and units.
- Define exception categories.
- Develop a data-quality measurement framework.

**Completion criteria:** Data-quality rules and measurement criteria are documented.

### Week 4 – Terminology and Interoperability
- Review existing LOINC codes.
- Assess terminology mapping coverage.
- Identify terminology inconsistencies.
- Define unit standardisation requirements.
- Prepare an OMOP mapping specification.

**Completion criteria:** Terminology governance and interoperability specifications are documented.

### Week 5 – Dashboard and Testing
- Define dashboard requirements.
- Develop initial dashboard views.
- Display key data-quality indicators.
- Prepare test scenarios.
- Perform initial user acceptance testing.

**Completion criteria:** Dashboard prototype and testing documentation are ready.

### Week 6 – Project Closure
- Review all project deliverables.
- Consolidate findings and recommendations.
- Prepare an implementation roadmap.
- Document lessons learned.
- Prepare final project presentation.

**Completion criteria:** Final project report and portfolio documentation are complete.

## 4. Dependencies

1. Dataset assessment depends on access to the selected dataset and its documentation.
2. Data-quality rules depend on understanding the available dataset fields.
3. LOINC and unit standardisation depend on the initial data assessment.
4. OMOP mapping specifications depend on terminology and data-field assessment.
5. Dashboard development depends on the availability of defined quality indicators.
6. Final reporting depends on completion of the preceding activities.

---

## 5. Schedule Management

- Progress will be reviewed weekly.
- Delayed activities will be reassessed for their impact on dependent tasks.
- Changes to scope or milestones will be documented.
- Any assumptions or limitations will be recorded.
- The schedule will be updated when necessary.

**Note:** This schedule represents a proposed project plan for a portfolio case study using public data. It does not represent a confirmed hospital implementation timeline.
